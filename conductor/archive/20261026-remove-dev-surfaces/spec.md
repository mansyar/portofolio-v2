# Remove Dev Surfaces and Admin Dead Ends — Specification

> Requirements are stable. Once an `FR`, `NFR`, or `AC` ID is approved, do not
> renumber it. If a requirement is removed, mark it `Withdrawn` instead of
> deleting it.

## Overview

Remove the TanStack starter's demo routes and their only data dependency from the
shipped application, then make the admin dashboard tell the truth: both currently
disabled quick actions already have real routes, and the "System Status" panel displays
hardcoded operational figures. The track also corrects the one stale Phase 9 status in
`docs/PROGRESS.md`.

## Problem / Motivation

Seven demo routes remain registered and are present in the built output. One of them
exposes an unauthenticated POST server function that writes `todos.json`; the production
image runs as non-root against a root-owned `/app`, so the write fails with `EACCES` and
the endpoint returns a public 500. `/demo/api/names` is a second public endpoint. All
demo pages use off-brand gradient UI, have no inbound links, and sit at 0% coverage.

On the admin dashboard, "View All" and "Draft New Post" are deliberately disabled with
TODO comments even though `/admin/messages` and `/admin/blog/new` are fully implemented.
The same page reports Uptime 99.9%, CPU 12%, Memory 456MB, and Disk 45% as fixed
literals. This undermines the CMS's credibility and the owner's engineering showcase.

`docs/PROGRESS.md` says Phase 9 is complete in the header and section, but planned in the
roadmap table.

## Goals & Success Metrics

- **Goal:** No development/demo surface is registered or shipped, and every dashboard
  action shown to the admin works.
- **Metric:** 0 routes under `/demo`; 0 demo chunks or demo page strings in a clean
  build; 2 previously disabled actions navigate to real routes; 0 hardcoded system
  metrics; 1 status row reconciled; all configured gates exit 0.

## Scope

### In Scope

- Delete the seven files under `src/routes/demo/` and regenerate the committed route
  tree.
- Delete `src/data/demo.punk-songs.ts`, whose only importers are three demo routes.
- Wire "View All" to `/admin/messages` and "Draft New Post" to `/admin/blog/new`; remove
  both stale TODO comments.
- Remove the hardcoded System Status block from the admin dashboard.
- Mark Phase 9 complete in the `docs/PROGRESS.md` roadmap table, matching its header and
  section.
- Add regression coverage for the removed route surface and the two dashboard links.
- Verify a clean production build contains no demo route artifacts.

### Out of Scope

- New admin features, dashboard redesign, or real infrastructure monitoring.
- Redirects for old `/demo/*` bookmarks; the routes were never linked and will 404.
- Removing other unused dependencies (for example `web-vitals`) or upgrading anything.
- Fixing the 22 existing lint warnings or the R1–R7 contrast debt.
- Any `convex/` schema, function, or deployment change.
- `/resume`, content freshness, or other roadmap features.

## Edge Cases

- **Stale build artifacts:** `.output/` may still contain old demo chunks; AC-2 runs after
  removing `.output` and rebuilding.
- **Route tree regeneration:** deleting route files without regenerating leaves invalid
  imports and fails typecheck; the build regenerates it, and the diff is reviewed.
- **Trailing slash:** the messages route is declared as `/admin/messages/`; the link
  targets the generated path key `/admin/messages`, which typecheck validates.
- **Old bookmarks:** `/demo/*` now returns the app's 404 by design; no redirect is added.
- **Test isolation:** the dashboard test must mock Convex queries and the router,
  following the existing `src/routes/__tests__/` pattern; no live backend is required.
- **Coverage denominator:** deleting untested demo files can only raise measured
  coverage; the 3% floor is unaffected.
